## Directory Purposes

**`app/`:**
- Purpose: All application logic
- Contains: Python modules for FastAPI app, data handling, web scraping, extraction logic
- Key files: `main.py` (entry), `schemas.py` (data contracts), `extractor.py` (core logic)

**`static/`:**
- Purpose: Frontend assets served to browser
- Contains: Single HTML file with embedded CSS and JavaScript
- Key files: `index.html` (entire UI)

**`.planning/`:**
- Purpose: Project management and documentation
- Contains: Analysis documents, phase plans, context capture
- Key files: None in current run (generated by `/gsd-*` commands)

## Key File Locations

**Entry Points:**
- `app/main.py`: FastAPI application definition, route handlers, startup initialization
- `static/index.html`: Web UI entry point (served by `GET /` route)

**Configuration:**
- `requirements.txt`: Python package dependencies
- `.env`: Environment variables (not in repo; created locally, contains `LLM_API_KEY`, etc.)
- `.gitignore`: Specifies ignored files/dirs (venv, cache, db, .env)

**Core Logic:**
- `app/schemas.py`: Data model definitions (what a briefing looks like)
- `app/extractor.py`: Text-to-briefing transformation (heuristic + LLM extractors)
- `app/fetcher.py`: HTML fetching, text extraction, robots.txt compliance
- `app/db.py`: SQLite cache management, persistence

**Testing:**
- `test_smoke.py`: Unit tests that run without network (text extraction, heuristic briefing generation)

**Documentation:**
- `SPEC-sales-intel.md`: Complete project specification, requirements, scope decisions

**Database:**
- `briefings.db`: SQLite database created at runtime; stores cached briefings (gitignored)

## Naming Conventions

**Files:**
- `*.py`: Python modules in `app/` follow `snake_case_with_purpose.py` pattern
  - `main.py`: Entry point
  - `schemas.py`: Data model definitions
  - `extractor.py`: Core extraction logic
  - `fetcher.py`: External I/O
  - `db.py`: Persistence
- `*.html`: Single file UI at `static/index.html` (no split components)
- Tests: `test_*.py` (pytest convention) at root level for integration tests

**Directories:**
- `app/`: Package directory; uppercase would indicate constants/enums
- `static/`: Standard web asset directory name
- `.planning/`, `.git/`: Hidden directories (dot prefix) for metadata

**Python Modules:**
- Class names: `PascalCase` (e.g., `HeuristicExtractor`, `LLMExtractor`, `FetchError`, `Briefing`)
- Function names: `snake_case` (e.g., `gerar_briefings`, `extrair_texto`, `pode_raspar`)
- Constants: `UPPER_SNAKE_CASE` (e.g., `USER_AGENT`, `TIMEOUT`, `MAX_BYTES`, `DB_PATH`, `VALIDADE`)

**HTTP Routes:**
- `/api/*`: Reserved for API endpoints (JSON requests/responses)
- `/static/*`: Reserved for asset serving
- `/health`, `/`: Health check and UI root

## Where to Add New Code

**New Feature (e.g., additional extraction method):**
- Primary code: Add new extractor class in `app/extractor.py` implementing `Extractor` protocol
- Tests: Add test case in `test_smoke.py` or create new `test_extractor.py`
- No changes needed elsewhere (pluggable design)

**New API Endpoint (e.g., admin panel):**
- Add route handler function to `app/main.py` with `@app.get()` or `@app.post()` decorator
- If returning HTML, add file to `static/` or return from handler
- If requiring data model, add to `app/schemas.py`

**New Component/Module (e.g., email notification system):**
- Create new file in `app/` (e.g., `app/notifier.py`)
- Follow pattern: Keep I/O separate from business logic
- Import in `app/main.py` if it's called from routes
- Add to `requirements.txt` if new external dependencies needed

**Utilities/Helpers:**
- Shared functions: Add to existing module where they belong (`fetcher.py` for web utils, `extractor.py` for extraction utils, `db.py` for persistence utils)
- Don't create `utils.py` (keep modules focused by responsibility)

**Persistent Data (new tables/schema):**
- Add table creation in `app/db.py` (within `criar_tabelas()`)
- Add CRUD functions in same file
- Update `.env` template with any new config needed

**Frontend UI Enhancements:**
- Edit `static/index.html` directly
- No build system; vanilla JavaScript and CSS
- Keep inline (no separate files) to keep deployment simple

## Special Directories

**`.venv/`:**
- Purpose: Python virtual environment (project-isolated dependencies)
- Generated: Yes (created by `python -m venv .venv`)
- Committed: No (gitignored)
- Delete and recreate with: `python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`

**`__pycache__/`:**
- Purpose: Python bytecode cache
- Generated: Yes (automatic during import)
- Committed: No (gitignored)
- Safe to delete; recreated on next run

**`.pytest_cache/`:**
- Purpose: Pytest test result cache
- Generated: Yes (by pytest)
- Committed: No (gitignored)
- Safe to delete

**`briefings.db`:**
- Purpose: SQLite database file containing cached briefings
- Generated: Yes (created by app at runtime if doesn't exist)
- Committed: No (gitignored, but should be backed up in production)
- Structure: Single table `briefings` with columns `url` (primary key), `briefing` (JSON), `extrator` (string), `coletado_em` (ISO timestamp)

## Project Initialization

**First time setup:**
```bash
# Create virtual environment
python -m venv .venv
source .venv/bin/activate  # or .venv\Scripts\activate on Windows

# Install dependencies
pip install -r requirements.txt

# Run tests (no network required)
pytest test_smoke.py

# Start development server
uvicorn app.main:app --reload
```

**Environment setup:**
- Copy `.env.example` to `.env` (if it exists in docs; not in repo currently)
- Set `LLM_API_KEY` if using LLM extractor; leave unset to use heuristic fallback
- No other config needed for development

**Database:**
- Created automatically on first request to API
- Stored as `briefings.db` in project root (same dir as `app/`)
- 7-day TTL enforced in code; no manual cleanup needed

## Import Patterns

**Within app:**
- Relative imports for sibling modules: `from .schemas import Briefing` in `main.py`
- No circular imports; dependency graph is acyclic
- Order: `app/schemas.py` has no dependencies, `app/extractor.py` depends on schemas, `app/main.py` depends on all others

**Third-party:**
- Standard library first: `from datetime import datetime`, `import json`
- Then external: `from fastapi import FastAPI`, `import httpx`, `from bs4 import BeautifulSoup`
- Then local: `from .schemas import ...`
